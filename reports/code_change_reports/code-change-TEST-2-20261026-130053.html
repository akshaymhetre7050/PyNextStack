DEFECT ANALYSIS — TEST-2 ────────────────────────────────────────────────────────── Summary : user_exists() treats "email OR username taken" as "email AND username taken" Priority : P3-Medium Affected : app/routers/users.py → user_exists() (lines 18-26) Root Cause : single-element $or wrapping one dict with both fields ⇒ logical AND Stack Trace : None provided (logic defect, no exception) Expected : 400 "The email or username is already in use." when EITHER field exists Regression : No existing test (tests/tests.py only had an SMTP smoke test) ────────────────────────────────────────────────────────── Confluence : No relevant pages in space SD (only a Saleor overview)

Root cause

  1. What is wrong: user_exists built {"$or": [{"email": e, "username": u}]}.
  2. Why it is wrong: a $or with one element is the same as that element alone, and a dict with two keys means "both match". The query was an AND.
  3. Correct behaviour: {"$or": [{"email": e}, {"username": u}]}, so a match on either field is detected.
  4. Impact scope: three callers: register.create_user, users.create_user, users.check_user_exists.

Live reproduction on unfixed main (running server, port 8000)
