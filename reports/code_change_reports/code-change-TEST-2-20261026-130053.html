Outcome. user_exists() now detects an existing user when either the email or the username is taken. The fix is 5 lines and is covered by 11 new pytest tests. These tests were run against both the unfixed main (3 regression tests fail) and the fix (all pass). Three reviews found no blockers.

Important caveat (verified live). The repo already has unique MongoDB indexes on email and username, so duplicate documents were never actually written. On main the real symptom is a generic 500 on duplicate registration, not the 200 that the Jira repro step suggested. After this fix the handler raises the intended 400, but TEST-3 (catch-all except Exception) still converts it to 500. TEST-3 must be merged for the user-visible message to change.

Defect analysis card

DEFECT ANALYSIS — TEST-2 ────────────────────────────────────────────────────────── Summary : user_exists() treats "email OR username taken" as "email AND username taken" Priority : P3-Medium Affected : app/routers/users.py → user_exists() (lines 18-26) Root Cause : single-element $or wrapping one dict with both fields ⇒ logical AND Stack Trace : None provided (logic defect, no exception) Expected : 400 "The email or username is already in use." when EITHER field exists Regression : No existing test (tests/tests.py only had an SMTP smoke test) ────────────────────────────────────────────────────────── Confluence : No relevant pages in space SD (only a Saleor overview)

Root cause

  1. What is wrong: user_exists built {"$or": [{"email": e, "username": u}]}.
  2. Why it is wrong: a $or with one element is the same as that element alone, and a dict with two keys means "both match". The query was an AND.
  3. Correct behaviour: {"$or": [{"email": e}, {"username": u}]}, so a match on either field is detected.
  4. Impact scope: three callers: register.create_user, users.create_user, users.check_user_exists.

Live reproduction on unfixed main (running server, port 8000)

StepRequestResponse
1POST /api/v1/register/ {username: tst2a, email: tst2@example.com}200 user created
2POST /api/v1/register/ {username: tst2b, email: tst2@example.com}500 "An error occurred while creating the user."
3Mongo count for tst2@example.com1 document (the unique index email_1 blocked the duplicate)

Test users were deleted afterwards. The 500 happens because user_exists wrongly returned False, insert_one then raised DuplicateKeyError, and the catch-all turned that into a 500.
